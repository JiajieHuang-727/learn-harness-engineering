# 基准任务集

Project 06 的固定考卷。弱 harness、强 harness、清理后、删掉某个 harness 组件之后，都跑这一套。

定稿日期：2026-10-12。第一次运行开始后不要改任务、输入、通过条件或评分规则。发现题目有歧义时，记在当次运行记录里，不要回头改考卷。

这不是 `feature_list.json`，也不是 `scripts/benchmark.sh`。功能清单可以随实现更新。这五条任务保持不动。

## 共同规则

每次运行前：

1. 在该次运行的应用目录执行 `npm install`（依赖已在时可以跳过）和 `npm run dev`。
2. 使用干净数据。若应用里有重置入口，先重置。否则退出应用，删掉启动日志里 `Data directories initialized` 打印的那个 `knowledge-base-data` 目录，再重新启动。
3. 同一次对比里，模型、任务顺序、允许的人工重试上限保持相同。这里的上限是每条任务最多 2 次重试（一共最多做 3 次）。
4. 只通过应用界面操作。不要改代码来让某一条任务通过。
5. 一条任务结束后立刻记分，不要等五条都做完再回忆。

每条任务只记三种结果：

| 结果 | 含义 |
|------|------|
| 通过 | 全部通过条件都满足，且没有下列缺陷 |
| 带缺陷完成 | 主要结果达到了，但命中了一条缺陷 |
| 失败 | 用完重试次数后，主要结果仍没有达到 |

缺陷只记这些，临时看不顺眼的问题不算：

- 必须改用开发者工具或控制台才能完成界面该做的动作
- 答案、列表或日志里的关键字段缺失、截断到无法核对，或指向错误文档
- 重启后文档或这条问答历史消失
- 应用崩溃、窗口空白，或命令行里出现未处理异常

重试：同一步骤因失败又做了一次，计 1 次重试。第一次就通过则重试次数为 0。

## T1 导入一篇文档

输入文件固定为该次运行目录下的 `data/sample-documents/retrieval-plan.md`。

步骤：

1. 用界面上的文件选择导入这个文件。
2. 若选择文件后列表没有变化，打开开发者工具，执行一次 `window.knowledgeBase.documents.import("<该文件的绝对路径>")`。这一次记为缺陷，并计 1 次重试。

通过条件：

- 文档列表里出现该文档，标题为 `Retrieval Plan`。
- 能看到文件名或大小，足以确认不是空条目。
- 启动 `npm run dev` 的终端里有一条 JSON 日志，包含 `IMPORT_DOCUMENT` 或 `Document imported`，以及这个文件路径。

## T2 构建索引

步骤：

1. 打开 T1 导入的文档。
2. 点击 `Index Document`。
3. 索引结束后点击 `Show Chunks`。

通过条件：

- 列表或详情里该文档状态为 `indexed`。
- 至少显示 2 个 chunk，并且每个 chunk 能看到序号和非空正文。
- 终端里有一条 JSON 日志，包含 `START_INDEXING` 或 `Document indexed`。

## T3 回答一个带引用的问题

问题原文固定，不要改写：

```text
How does the indexing pipeline split documents into chunks?
```

步骤：

1. 在问答面板提交上面这句话。
2. 阅读回答、引用和置信度。

通过条件：

- 回答不是空的，并且提到按段落或大约 500 字符切分。
- 至少一条引用的文档标题是 `Retrieval Plan`，摘录能对上 `retrieval-plan.md` 里的分块说明，而不是另一篇文档。
- 置信度显示为 85%，或界面上的等价数值 0.85。
- 终端里有一条 JSON 日志，包含 `ASK_QUESTION` 或 `Answer generated`，并且带有引用数量或置信度。

未索引就提问导致没有引用：先回到 T2。这计为 T3 的一次重试，不把 T2 改成失败。

## T4 用运行时日志确认可观测性

不新增操作。只检查 T1 到 T3 已经打出来的终端输出。

通过条件：这三条日志都能在同一次运行的终端里找到，而且每一条都是 JSON，并同时包含时间戳、级别、服务名、消息：

| 动作 | 消息里要能对上 |
|------|----------------|
| 导入 | `IMPORT_DOCUMENT` 或 `Document imported` |
| 索引 | `START_INDEXING` 或 `Document indexed` |
| 提问 | `ASK_QUESTION` 或 `Answer generated` |

只在界面上看到结果、终端没有对应 JSON 日志，这条失败。

## T5 关掉再打开，状态还在

步骤：

1. 完全退出应用，确认 `npm run dev` 的进程已经结束。不要删数据目录。
2. 在同一目录再次执行 `npm run dev`。
3. 查看文档列表，并打开对话历史。

通过条件：

- `Retrieval Plan` 仍在列表中，状态仍是 `indexed`。
- 历史里仍有 T3 那句英文问题，以及当时的回答。
- 不需要重新导入或重新索引。

历史面板打不开，或只能在数据文件里看到记录、界面上看不到，这条失败。
